# 升级计划 v1：仅面向 Vite 8 最新 API 的收敛

## 目标

在已经完成 Vite 8 适配和 Bun 迁移的基础上，不再保留 Vite 3-7 的兼容写法，只面向当前锁定的 `vite@8.0.16` 收敛插件实现。

## 改动范围

### 1. 使用 Vite 8/Rolldown 类型

- 将源码里从 `rollup` 导入的插件上下文类型改为从 `vite` 导出的 `Rollup` 命名空间类型。
- 保留 `source-map` 的 `RawSourceMap` 类型。
- `src/utils/error.ts` 的 `RollupError` 同步改为 Vite 导出的类型。
- 验证通过后，从 `package.json` 移除直接的 `rollup` devDependency。

### 2. 使用 Vite 8 `normalizePath`

- 用 `vite` 导出的 `normalizePath` 替代 `slash`。
- 修改位置：
  - `src/template.ts`
  - `src/utils/descriptorCache.ts`
- 验证通过后，从 `package.json` 移除 `slash` devDependency。

### 3. 简化 Vite 8 resolved alias 逻辑

- Vite 8 resolved config 中 `config.resolve.alias` 是数组。
- 删除对象 alias 兼容分支，只保留数组检查和 push。

### 4. 使用 Vite 8 plugin context environment

- 在 `load` / `transform` 钩子中，用 `this.environment` 判断 SSR/server 环境。
- 删除 `opt.ssr` 回退逻辑，只使用 Vite 8 插件上下文提供的 `environment.config.consumer`。

## 验证

按顺序执行：

1. `bun install`
2. `bun run build`
3. `bun run vitest run test/smoke.spec.ts`
4. `playground` 下执行 `../node_modules/vite/bin/vite.js build`
5. 启动 playground dev server 后递归请求 `/main.js` 模块图，确认无 500 转换错误

完整 `bun run test` 在当前 Nix 环境仍会受 Puppeteer Chromium 系统库缺失影响；这不作为本轮代码收敛的阻塞条件。
